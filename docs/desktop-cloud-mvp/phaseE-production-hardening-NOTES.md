# Phase E — Production hardening of the Linux Desktop Cloud VPS

## Goal
Make the Allternit Desktop Cloud Linux MVP deployment on `mail.news.allternit.com` production-ready: secure onboarding, hardened Incus TLS, observable health, automated deploys, verified backups, and a runnable operator runbook.

## What changed

### 1. Self-hosted onboarding auth
- Added `ALLTERNIT_SELF_HOSTED_SETUP_TOKEN` to `/etc/allternit-api/api.env` (32-byte hex, generated by `deploy.sh`).
- Added middleware in `cmd/allternit-api/src/auth.rs` that accepts the token via the `X-Allternit-Self-Hosted-Token` header for bootstrap endpoints (`/health`, `/api/v1/desktop-health`, `/api/v1/agents`, `/api/v1/desktop-templates`).
- Added `GET /api/v1/desktop-health` in `cmd/allternit-api/src/bot_desktop_admin.rs` to report Incus/substrate reachability.
- Added the header to CORS `allow_headers` in `cmd/allternit-api/src/main.rs`.
- The platform shell sends the header on every request when `VITE_ALLTERNIT_SELF_HOSTED_TOKEN` is set (`surfaces/ai.allternit.com/src/integration/api-client.ts`).

### 2. Incus TLS hardening
- `cmd/allternit-computer-cloud/src/substrate.rs` now loads the Incus CA certificate from `INCUS_CA_CERT` and verifies it by default (`INCUS_INSECURE_SKIP_VERIFY=false`).
- `deploy.sh` copies `/var/lib/incus/server.crt` to `/etc/allternit-api/incus/ca.crt` and the client cert/key into the same directory.
- The VPS `api.env` sets `INCUS_CA_CERT=/etc/allternit-api/incus/ca.crt` and `INCUS_CLIENT_CERT` / `INCUS_CLIENT_KEY`.

### 3. Production logging
- Added `ALLTERNIT_LOG_FORMAT=json` to the VPS env file.
- JSON request logs include request IDs and structured fields for log aggregation.

### 4. Automated VPS deploy workflow
- Added `.github/workflows/deploy-desktop-cloud-vps.yml`.
- Triggers on pushes to `main` that touch desktop-cloud paths.
- Builds the release binary, deploys via `infrastructure/vps-desktop-cloud/deploy.sh`, seeds the e2e bot/template, and runs the Playwright e2e test remotely.

### 5. Backup service
- `infrastructure/vps-desktop-cloud/backup-all-running.sh` lists running `allternit-bot-*` Incus instances and exports each to MinIO/S3.
- `cmd/allternit-computer-cloud/guest/backup-to-s3.sh` is self-contained: configures `mc alias`, creates the bucket if missing, uploads the tarball, and verifies the object with `mc stat`.
- `allternit-desktop-backup.timer` fires hourly.
- `allternit-desktop-backup.service` runs the wrapper as a oneshot.
- **Fix applied during Phase E**: `backup-to-s3.sh` was not executable after checkout, causing the first timer fire to fail. `deploy.sh` now runs `chmod +x` on it, and the executable bit was set on the VPS manually.

### 6. Health watchdog
- `infrastructure/vps-desktop-cloud/health-check.sh` checks `/health` and, when a self-hosted token is present, `/api/v1/desktop-health`. It logs to `/var/log/allternit-api/health.log` and exits non-zero on failure.

### 7. E2E seed script
- `infrastructure/vps-desktop-cloud/seed-e2e.sh` creates the `desktop-cloud-e2e-bot` agent and the `Allternit Desktop` template using the self-hosted token, so CI can run the Playwright test without Clerk credentials.

### 8. Frontend bot-selection race fix
- `surfaces/ai.allternit.com/src/views/desktop-cloud/DesktopCloudAdminView.tsx` now uses one-shot refs (`initialBotSetRef`, `initialTemplateSetRef`) so the default-bot selection only runs on the first successful data load.
- The bot list is now deduplicated by name, preferring the canonical API list over the agent store's local fallback catalog. This removes duplicate display names that could confuse the e2e selector.
- `handleProvision` reads the live DOM value from attached refs as a last defense against stale React closures.

### 9. Incus VNC proxy port recovery
- `cmd/allternit-computer-cloud/src/substrate.rs` gained `list_instance_names()` to enumerate existing Incus instances.
- `cmd/allternit-computer-cloud/src/driver.rs` gained `recover_ports()`, called once at API startup after the Incus health check.
- It scans every configured host, reads each instance's VNC proxy device config, seeds the in-memory port map, and starts the allocator at `max(recovered_port) + 1`. This prevents new spawns from retrying already-bound host ports after a service restart.
- `cmd/allternit-api/src/main.rs` calls `driver.recover_ports().await` right after `driver.health_check().await`.

### 10. Operator runbook
- `docs/desktop-cloud-mvp/RUNBOOK.md` covers initial deploy, re-deploy, secret rotation, certificate rotation, log reading, health checks, e2e re-run, snapshot/backup restore, image import, and known limitations.

cd surfaces/ai.allternit.com
VITE_ALLTERNIT_GATEWAY_URL=https://mail.news.allternit.com \
VITE_ALLTERNIT_SELF_HOSTED_TOKEN=$(ssh -i ~/.ssh/id_tailscale root@mail 'grep ALLTERNIT_SELF_HOSTED_SETUP_TOKEN /etc/allternit-api/api.env | cut -d= -f2') \

## Known issues / next steps
- `api-client.ts` exceeds the soft LOC cap because it predates the cap. A future phase should split it into domain-specific clients (auth, agents, desktop-cloud, etc.).
- Windows desktops still require a KVM-capable host; the current VPS is a VM without nested KVM.
- macOS desktops require Apple Silicon + Tart; the current fleet only validates macOS locally.
