# Events API

A session's event stream is append-only and ordered by monotonically increasing `sequence` numbers. Clients can consume it through Server-Sent Events (SSE), WebSocket, or by appending run events produced by an agent runtime.

All routes are nested under `/api/v1/beta/sessions/:id`.

> Base URL: `http://localhost:8013/api/v1`  
> Auth: `Authorization: Bearer <clerk_jwt>`

---

## Stream events (SSE)

`GET /beta/sessions/:id/events[?after=<sequence>]`

Returns an SSE stream. Each event has:

- `id` — the sequence number
- `event` — the event type
- `data` — JSON payload

If `after` is supplied, the server streams events with a sequence greater than that value; otherwise it starts from the beginning.

### Example

```bash
curl -N "http://localhost:8013/api/v1/beta/sessions/sess_01J3X8X8X8X8X8X8X8X8X8X8/events" \
  -H "Authorization: Bearer $CLERK_JWT" \
  -H "Accept: text/event-stream"
```

### SSE frame

```text
event: content_block_delta
id: 3
data: {"message": "Looking up the ticket..."}
```

## Stream events (WebSocket)

`GET /beta/sessions/:id/events/ws[?after=<sequence>]`

Upgrades the connection to a WebSocket. The server sends JSON messages of the form:

```json
{"sequence": 3, "type": "content_block_delta", "data": {"message": "Looking up the ticket..."}}
```

### Example (JavaScript)

```javascript
const ws = new WebSocket(
  'ws://localhost:8013/api/v1/beta/sessions/sess_01J3X8X8X8X8X8X8X8X8X8X8/events/ws?after=0'
);
ws.onmessage = (msg) => {
  const event = JSON.parse(msg.data);
  console.log(event.sequence, event.type, event.data);
};
```

## Append a run event

`POST /beta/sessions/:id/events`

Runtimes call this endpoint to append progress events to a session. The request is rejected if the session is archived or if the appended usage would exceed the session budget.

### Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `type` | string | yes | One of the appendable run event types below. |
| `data` | object | no | Event payload. Defaults to `{}`. |
| `usage` | object | no | Token/turn/tool usage delta to apply. |

**Usage object**

| Field | Type | Description |
|-------|------|-------------|
| `tokens` | integer | Tokens consumed by this event. |
| `turns` | integer | Turns consumed by this event. |
| `tool_calls` | integer | Tool calls consumed by this event. |

### Appendable run event types

| Type | Description |
|------|-------------|
| `thinking_delta` | Intermediate reasoning fragment. |
| `content_block_delta` | New content produced by the model. |
| `tool_calls` | Model requested one or more tool calls. |
| `refusal` | Model refused the request. |

### Example

```bash
curl -X POST http://localhost:8013/api/v1/beta/sessions/sess_01J3X8X8X8X8X8X8X8X8X8X8/events \
  -H "Authorization: Bearer $CLERK_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "type": "content_block_delta",
    "data": {"message": "Looking up the ticket..."},
    "usage": {"tokens": 12, "turns": 0, "tool_calls": 0}
  }'
```

### Response

```json
{
  "accepted": true,
  "event": {
    "id": "evt_01J3X8X8X8X8X8X8X8X8X8X8",
    "sequence": 3,
    "session_id": "sess_01J3X8X8X8X8X8X8X8X8X8X8",
    "type": "content_block_delta",
    "data": {"message": "Looking up the ticket..."}
  }
}
```

If the usage delta would exceed the session budget, `accepted` is `false` and a `budget_exceeded` event is appended instead.

## Interrupt a session

`POST /beta/sessions/:id/interrupt`

Appends a `user_interrupt` event to an active session. Archived sessions cannot be interrupted.

### Request body

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `data` | object | yes | Arbitrary interrupt context. Must be an object. |

### Example

```bash
curl -X POST http://localhost:8013/api/v1/beta/sessions/sess_01J3X8X8X8X8X8X8X8X8X8X8/interrupt \
  -H "Authorization: Bearer $CLERK_JWT" \
  -H "Content-Type: application/json" \
  -d '{"data": {"reason": "user_pressed_stop"}}'
```

### Response

```json
{
  "event": {
    "id": "evt_01J3X8X8X8X8X8X8X8X8X8X8",
    "sequence": 7,
    "session_id": "sess_01J3X8X8X8X8X8X8X8X8X8X8",
    "type": "user_interrupt",
    "data": {"reason": "user_pressed_stop"}
  }
}
```

## System event types

These events are generated by the platform, not appended by callers:

| Type | Source | Meaning |
|------|--------|---------|
| `session_created` | platform | Session record was created. |
| `budget_updated` | platform | Budget limits changed. |
| `budget_exceeded` | platform | A usage delta would have exceeded a limit. |
| `user_interrupt` | platform | A caller interrupted the session. |
| `session_archived` | platform | The session was archived. |

---

## Status codes

| Status | Meaning |
|--------|---------|
| 200 | Append or interrupt succeeded. |
| 400 | Unsupported event type, invalid `data`, or session is archived. |
| 404 | Session not found or not owned by caller. |
