# OpenTelemetry metrics emitted by gizzi-code

When OpenTelemetry (OTel) is enabled via `experimental.openTelemetry`, `gizzi-code` emits OpenTelemetry spans for AI SDK calls. The exact metrics, spans, and attributes depend on the AI SDK provider in use and the OTel collector configured in your environment.

This page describes the conceptual categories of telemetry you can expect. Exact metric names may change between releases; inspect your OTel collector for the current names emitted by your installed version.

## Enable OTel

Add to your user config (`~/.config/gizzi-code/config.toml`):

```toml
[experimental]
openTelemetry = true
```

Or set the environment variable:

```bash
export GIZZI_EXPERIMENTAL_OPEN_TELEMETRY=true
```

`gizzi-code` also respects standard OTel environment variables such as `OTEL_EXPORTER_OTLP_ENDPOINT`, `OTEL_SERVICE_NAME`, and `OTEL_RESOURCE_ATTRIBUTES`.

## Span categories

### AI SDK calls

The AI SDK emits spans around model calls. Typical attributes include:

- `operation.name` / `ai.operation.name` — the SDK operation name
- `ai.model.id` / `ai.model.provider` — the model and provider used
- `ai.usage.prompt_tokens` / `ai.usage.completion_tokens` — token usage
- `ai.response.finish_reason` — the finish reason

These spans are generated by the AI SDK, not by `gizzi-code` directly.

### Tool calls

When the AI SDK invokes a tool through the Tool Belt, the provider may emit spans for tool dispatch and execution. Tool spans describe the tool name and outcome but do **not** include the actual shell command, patch contents, or sensitive arguments unless your collector or provider configuration captures them.

### Stream events

For streaming providers, the AI SDK may emit events for stream start, content deltas, and stream completion. These are provider-specific.

## Metrics from spans

Some OTel collectors can derive metrics (counters and histograms) from spans. You can use these derived metrics to build dashboards for:

- API request counts and durations by provider/model
- Tool call counts and durations by tool name
- Token usage per request
- Error rates and finish reasons

`gizzi-code` does not emit standalone OTel metrics directly; it relies on the AI SDK spans and your collector's span-to-metric capabilities.

## Privacy and security notes

- OTel export is disabled by default.
- Prompt content is not automatically included in AI SDK spans; what is captured depends on your provider and collector configuration.
- Tool spans do not include raw command text or patch contents unless explicitly configured at the collector or provider level.
- Store OTLP endpoints, headers, and API keys in environment variables or a secrets manager; do not commit them to version control.
