v3 — audited v2 against decision-queue and incident-response products, not just other "agent panel" UIs. Full findings and failure scenarios in AUDIT_NOTES.md. What changed here and why:
  • Archive + Share are back (v1 had them, v2 silently dropped them) via a per-row ⋯ menu — archive()/share() are real, distinct Rails Mail actions, not the same thing as decide().
  • Unread state restored (v2 had none at all — a heavy user with dozens of threads couldn't tell new from seen) plus a real Archived tab, so resolved/archived threads stop inflating "All" forever.
  • Review cards always show the actual ask before offering Approve/Deny — modeled on PagerDuty/Linear always surfacing full context before an action, not a bare link a user could ignore. Code-diff requests show a stat line; non-diff decide() calls (a design choice, not a diff) show the question and the agent's recommended option inline, since decide() is strictly boolean — there's no such thing as a 3-way decision in the real API, only "approve the recommendation or not."
  • Accordion → "Open full thread" escalation, matching what Claude Code's Agent View actually does (inline preview, Enter for full transcript) — v2's banner cited that pattern but only built the inline half, with no escape hatch for a long-running thread.
  • Reservations and guard actions are now visible, not invisible — reserve()/guard() aren't human actions, but a lock held by one thread blocking another is exactly the kind of state this repo's own concurrent-session workflow needs surfaced (see GIZZI.md's "multiple concurrent Eoj/agent sessions" note).
  • Keyboard-first interaction (↑↓/j k navigate, Enter open, 1/2 approve/deny, a archive) — modeled on Linear Triage's number-key triage. This is also the piece that actually generalizes to a CLI list, unlike hover states or a fixed 400px panel.
  • Reduced-motion respected (pulse only animates under prefers-reduced-motion: no-preference); status is never color-only — every dot has a text label alongside it.
New sources (beyond Claude Code / GitHub Agents panel / Cursor, already cited in v2)

  • Linear Triage Intelligence — linear.app/now/how-we-built-triage-intelligence: AI suggestions shown with visible reasoning (hover tooltip + "thinking panel"), never silently auto-applied.
  • PagerDuty incidents — support.pagerduty.com/main/docs/incidents: filterable Timeline tab, Acknowledge/Escalate/Resolve action bar.
  • PagerDuty mobile app — support.pagerduty.com/main/docs/mobile-app: status-color banner (red→yellow on ack), swipe-to-Ack/Resolve, long-press push notification to Ack without opening the app.
  • GitHub notifications inbox — docs.github.com/.../managing-notifications-from-your-inbox: reason labels, Done vs Save (kept vs. archived-forever) as the volume-control mechanism.
  • GitHub Mobile push notifications — github.blog changelog, 2021-11-22 and 2021-04-01: on mobile, the notification itself is the only entry point to a deployment-approval dialog.
  • Slack mobile approval-request tutorial — docs.slack.dev/.../tutorials/mobile-request: Block Kit message with primary Approve / danger Deny buttons; on click, buttons are replaced in place with the decision (no dead state).
