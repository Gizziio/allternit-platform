Module 2: Standing Context & Personas

Learn how Allternit Cowork gives every agent session a memory layer and a default identity, so repeated work feels continuous instead of starting from zero every time.

5 lessons · ~35 minutes Source: packages/@allternit/cowork-engine

Personas as reusable identities

A persona is a named bundle of system prompt, allowed tools, and default flag. Instead of rewriting instructions for every task, a Cowork workspace selects a persona and lets it shape how the agent interprets the request.

The engine ships with three built-in personas in packages/@allternit/cowork-engine/src/personas/types.ts:

  • Researcher — gathers and cites information across sources, writes structured summaries.
  • Engineer — reads, writes, and debugs code; set as the default fallback.
  • Analyst — inspects datasets, produces visualizations, and reports findings.

Personas are userId-scoped. The store guarantees that only one persona per user is marked default, falling back to the alphabetically first persona if the invariant is ever violated. This means a workspace can always select an identity, even if the user has never configured one.

Identity principle: The persona is the first layer of standing context. It tells the agent what hat to wear before any task-specific memory is loaded.

Memory scoping

Memory entries in Cowork are not a single flat list. Each entry is scoped by userId, optionally narrowed by projectId or sessionId. This lets long-lived facts survive while short-term drafts stay isolated.

FieldScopeExample
userIdUser-widePreferred output format, name, timezone
projectIdProject-wideStack conventions, API base URL, style guide
sessionIdSession-onlyCurrent task, draft outputs, temporary context

The type enum in memory/types.ts classifies each entry:

  • fact — objective knowledge about the user, project, or domain.
  • preference — user tastes, defaults, and stylistic choices.
  • skill — reusable capabilities or procedures the user has taught the workspace.
  • context — general background for the current session or task.
typescript 
export type CoworkMemoryEntryType = 'fact' | 'preference' | 'skill' | 'context';

export interface CoworkMemoryEntry {
  id: string;
  userId: string;
  projectId: string | null;
  sessionId: string | null;
  content: string;
  type: CoworkMemoryEntryType;
  tags: string[];
  source: string | null;
  createdAt: Date;
}

Selecting context at runtime

When a task starts, the workspace loads the default persona, then queries memory in order of specificity: user-wide first, then project-wide, then session-only. The combined context is injected into the system prompt so the agent starts with the right background.

flowchart TD
    U[User opens Cowork workspace] --> P{Default persona set?}
    P -->|Yes| S[Use selected persona]
    P -->|No| D[Use Engineer built-in]
    S --> M{Memory query scope}
    D --> M
    M -->|userId| F[User-wide facts & preferences]
    M -->|projectId| R[Project conventions & decisions]
    M -->|sessionId| T[Session task context]
    F --> C[Compose system prompt + memories]
    R --> C
    T --> C
    C --> A[Agent executes task]

Skills as packaged context

Personas and memory are scoped to a workspace, but skills are reusable packages that can be shared across workspaces. The docs/public/skills/skill-format.md guide defines a skill as a directory with a SKILL.md manifest and an entrypoint module.

markdown 
---
name: run-tests
version: 1.0.0
description: Run the project test suite and summarize failures.
author: allternit
tags: [testing, ci]
tools: [bash, file.read]
---

# run-tests

Run the appropriate test command for the project. Prefer npm test, bun test, cargo test, or pytest based on the files present. After running, summarize the results.

The skill registry validates that each skill has the required front-matter fields, a non-empty tools array, and a valid semantic version. Malformed skills are reported at load time and are not surfaced to agents.

Skills can also declare progressive disclosure levels. A skill may expose only a create tool initially and reveal editing tools once the user asks to iterate. This keeps the context window focused and reduces the chance of the agent picking the wrong tool.

Skill principle: Package prompts, tools, and constraints once; load them into any workspace that needs the capability.

Capstone: Build a Cowork workspace initializer

Write a small TypeScript function that prepares a Cowork workspace for a new user and project. The function should use the real Cowork engine types and produce both personas and scoped memory.

Seed personas

Call ensureBuiltIns(userId) so Researcher, Engineer, and Analyst are available, and return the default persona.

Capture preferences

Store a preference memory entry at user scope for output format.

Capture project context

Store a fact memory entry at project scope describing the tech stack.

Recall by scope

Implement a helper that returns memories filtered by type and scope, ordered user → project → session.

Deliverable: async function initWorkspace(userId, projectId, prisma) that returns the default persona and at least one user-scoped and one project-scoped memory entry.
