Module 7: Agent Architectures & Workflows

Learn how Allternit structures agent behavior across sessions, workflow graphs, and orchestrated executor backends — turning single model calls into reliable multi-step systems.

6 lessons · ~50 minutes Source: packages/@allternit/workflow-engine

Managed agent lifecycle

Production agents are not one-shot completions. They are long-lived entities that need identity, memory, budgets, and lifecycle controls. The Allternit API exposes a managed lifecycle: create an agent, open a session, stream events, interrupt if needed, deploy on a schedule, and archive when finished.

1. Create an agent

POST /api/v1/agents registers an agent with a name, description, type, model, provider, system prompt, and harness config. The harness config mode must be one of byok, cloud, local, or subprocess.

bash 
curl -X POST http://localhost:8013/api/v1/agents \
  -H "Authorization: Bearer $ALLTERNIT_JWT" \
  -H "Content-Type: application/json" \
  -d '{
    "name": "support-agent",
    "description": "Triages support tickets and suggests replies.",
    "agent_type": "worker",
    "model": "allternit-balanced",
    "system_prompt": "You are a helpful support engineer. Be concise.",
    "harness_config": {"mode": "local"},
    "enabled_modes": ["chat"]
  }'

2. Create a session

POST /api/v1/beta/sessions binds the agent to a managed session with a budget. The platform seeds session_created and budget_updated events. Budgets cap tokens, turns, and tool calls.

3. Stream events

GET /api/v1/beta/sessions/:id/events opens an SSE connection. Runtime events such as thinking_delta, content_block_delta, tool_calls, and refusal append to the session transcript.

4. Interrupt and archive

POST /api/v1/beta/sessions/:id/interrupt appends a user_interrupt event. DELETE /api/v1/beta/sessions/:id archives the session and releases its active budget slot.

5. Deploy on a schedule

POST /api/v1/beta/deployments schedules the agent with a cron expression. Runs can be triggered manually via POST /api/v1/beta/deployments/:id/runs and completed via PATCH /api/v1/beta/deployments/:id/runs/:run_id.

Session contract: Budgets, events, and interrupts make the agent observable and controllable. The session is the unit of cost, state, and human oversight.

Workflow patterns: routing, chaining, parallelization

Single model calls rarely solve production tasks. The Allternit workflow engine expresses agent behavior as a graph of nodes and connections. The three fundamental patterns are routing, chaining, and parallelization.

PatternBest forEngine primitive
RoutingClassify input and dispatch to a specialist branchcondition:if
ChainingDependent steps where output feeds the next inputSequential connections
ParallelizationIndependent checks that merge into a resultloop:for-each with parallel=true

The engine builds a DAG from the workflow definition and executes nodes only after every dependency has completed. Node executors are pure functions registered by type, so custom behavior can be added without changing the scheduler.

Agent orchestrator

The @allternit/orchestrator package runs external agent executors in isolated sessions. It is vendor-neutral and backend-agnostic: the same primitives work for local terminals, mux-backed PTYs, cloud runners, and the ACI computer-use backend.

Session spec and completion contract

An ExecutorBackend spawns a session from a SessionSpec. The spec declares the working directory, launch command, isolation mode, and a notes file path. The notes file is the only completion signal; backends must not rely on process exit codes or heuristics.

typescript 
const spec: SessionSpec = {
  slug: 'refactor-gateway',
  workdir: '/Users/dev/allternit',
  vendor: 'kimi',
  mode: 'headless',
  launchCommand: 'gizzi exec --task ./task.md',
  isolation: 'worktree',
  notesFile: '.agent-notes.md',
  timeoutMs: 3_600_000,
};

const session = await backend.spawn(spec);
const outcome = await backend.watch(session, spec);
const footprint = await backend.footprint?.(session);

Verified send and isolation

The send method uses verified paste: it writes the prompt, reads the terminal back, and submits only when the pasted text matches. This prevents partial instructions from reaching the executor. When isolation is worktree, the orchestrator creates a linked git worktree on branch ao/<slug> so changes are isolated and reviewable.

Capstone: Orchestrate a multi-executor research workflow

Design an agent architecture that combines the managed lifecycle, workflow engine, and orchestrator.

Goal

Create an agent that receives a research question, routes it to either a web-search branch or a code-search branch, and synthesizes a cited answer.

Constraints

Use a condition:if router. Run the two search branches in parallel. Merge results into a final synthesis node.

Deliverable

A workflow JSON, the agent definition, and a sequence diagram showing session creation, event streaming, and archiving.

Stretch

Spawn a headless orchestrator session to run a code-search tool and return its footprint for review.
