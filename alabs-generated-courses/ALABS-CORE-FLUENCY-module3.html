Module 3: Description: Writing Effective Prompts and Skills

Learn how to describe work so an agent can do it reliably. This module covers prompt patterns, reusable skills, and the validation layer that keeps agent behavior predictable.

5 lessons · ~40 minutes Source: .agents/skills/agent-orchestrator

Prompts as contracts

A prompt is not a wish. In production it is a contract between the operator, the model, and the downstream code that consumes the output. If the contract is ambiguous, every integration downstream pays the cost in parsing logic, retries, and human review.

The 4D Description step from AI Fluency says: be explicit about the output shape, give the model a role and constraints, and provide examples at the boundary. Allternit encodes this in agent-definition.ts through the defineAgent factory, which validates a compact declarative definition against the full CreateAgentInput schema and the agent creation checklist.

typescript 
import { defineAgent } from '@/lib/agents/agent-definition';

const triageAgent = defineAgent({
  name: 'support-triage',
  description: 'Classifies support tickets and drafts first responses.',
  instructions: `You are a support triage assistant. Read the ticket, classify
    the issue into one of: Billing, Technical, Account, Feature Request.
    Draft a brief, empathetic first response. If sentiment is strongly
    negative or the issue mentions legal terms, set escalate to true and
    do not draft a response.`,
  capabilities: ['classify', 'respond'],
  tools: ['web_search', 'read_file'],
});
  • Role. Start with who the model is and what it is doing.
  • Output shape. State whether the result should be prose, JSON, CSV, or an artifact manifest.
  • Constraints. List hard bans and escalation rules explicitly.

Skills: reusable prompt-and-tool packages

A skill packages a prompt, a tool allowlist, and progressive disclosure into a single directory. Allternit skills live under ~/.allternit/skills/ and are declared by a SKILL.md manifest. The registry validates that the manifest exists, required fields are present, the version looks like semver, tools is a non-empty array, and entrypoint is a non-empty string.

gizzi-code can also load skills from ~/.config/gizzi/skills/ and .gizzi/skills/. Project-level skills override user-level skills by name, so a repository can ship its own conventions without breaking the user's global setup.

Skill lifecycle: manifest → registry validation → tool allowlist → progressive disclosure → agent invocation → review → iterate.

Reusable prompt patterns

The Allternit use-case playbooks demonstrate patterns that generalize across tasks. The support-triage playbook combines a role, a closed set of categories, an escalation rule, and a structured output schema. The legal-document playbook requires quoted evidence for every risk flag. The data-extraction playbook returns null for missing fields instead of hallucinating values.

PatternWhen to useExample
Role + constraintsAny agent with a bounded job“You are a support triage assistant…”
Closed categoriesClassification tasksenum: ["Billing", "Technical", "Account"]
Evidence quotingRisk or review tasks“Quote the relevant passage for each flag.”
Null for missingStructured extraction“If a field is missing or unreadable, use null.”

Capstone: Write a reusable skill

Design, validate, and test a skill for a real task in your workflow.

Scope

Pick one narrow task, such as reviewing a diff or summarizing a meeting transcript.

Manifest

Write a SKILL.md with required frontmatter and a least-privilege tools list.

Progressive disclosure

Define a basic level that surfaces one tool and a full level that unlocks the rest.

Validate

Run the skill through gizzi-code and verify it loads without registry errors.
