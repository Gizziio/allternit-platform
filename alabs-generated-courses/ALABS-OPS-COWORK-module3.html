Module 3: Plugins, Browser, and Document Tasks

Learn how Allternit Cowork delegates multi-step work to plugins, browser automation, and document parsers—while keeping the human in control through the Operator surface.

5 lessons · ~45 minutes Source: @allternit/browser-tools

Plugins and skills as task primitives

Cowork does not do everything itself. It delegates to specialized capabilities called plugins and skills. A plugin is usually a code-level integration that exposes one or more tools; a skill is a prompt-and-tool package declared in a SKILL.md manifest.

The SKILL.md format used by Allternit skills lives under ~/.allternit/skills/. Each skill directory contains a manifest and an entrypoint. The skill registry validates required frontmatter fields—name, version, description, tools, and entrypoint—and refuses malformed packages at load time. gizzi-code discovers local skills from ~/.config/gizzi/skills/, .gizzi/skills/, and any paths configured in config.toml.

markdown 
---
name: allternit/powerpoint
version: 0.1.0
description: Generate and edit .pptx presentations
tools:
  - create_presentation
  - add_slide
entrypoint: powerpoint.ts
---

## Progressive disclosure

- **basic**: create_presentation when the user asks for a new deck.
- **full**: add_slide when the user wants to extend an existing deck.
  • Least-privilege tool sets. Declare only the tools a skill needs.
  • Progressive disclosure. Reveal advanced tools only after trust or context grows.
  • Version pinning. Bump the version when behavior changes so Cowork can warn about drift.

Browser automation with OperatorBrowserView

The Allternit Computer Interface (ACI) lets agents observe and control a browser through screenshots, mouse/keyboard actions, and human-in-the-loop approvals. The web surface for this is OperatorBrowserView.tsx, which creates tasks against /api/v1/operator/browser/tasks and monitors their status.

Under the hood, @allternit/browser-tools provides type-safe browser control. It exposes session management, navigation, DOM extraction, and action tools. Each function returns a ToolResult so the Cowork loop can recover from failures instead of crashing. Safety checks block file:// URLs and other dangerous schemes before navigation.

Sessionbrowser.create_session, browser.close_sessionLifecycle and viewport

Document parsing and Office tasks

Document tasks use the same @allternit/office-file-parse package covered in the AGENTS-API RAG module. Cowork calls parseFileToText to turn Word, PowerPoint, Excel, and PDF files into plain text, then reasons over the result.

The combination is powerful: a single Cowork task can parse a quarterly report PDF, extract totals, open the company expense portal in the browser, fill the form with the parsed numbers, and save both a summary and a receipt. The task is broken into phases by the Cowork planner, each phase invoking the right plugin or browser tool.

Human-in-the-loop: Destructive actions and navigation to new sites pause for approval. Cowork is autonomous on known steps, not reckless.
