Module 5: Diligence: Safety, Privacy, and Verification

Diligence is the fourth D of AI fluency: treating safety, privacy, and verification as design constraints rather than afterthoughts. This module connects Allternit's security model, permission profiles, vault, and audit system.

5 lessons · ~40 minutes Source: surfaces/ai.allternit.com/src/lib/agents

DLP and prompt leak detection

The Allternit LLM gateway scans outgoing requests for secrets, PII, and prompt-injection patterns before they reach any provider. Detections can warn, redact, or block. Admin endpoints also let operators score user text against system prompts to detect accidental leakage.

Trust boundaries are clear: customer browsers and the gizzi-code CLI live in the customer environment; the Allternit API server enforces auth, rate limits, DLP, budgets, and routing; external providers receive only policy-checked requests.

ThreatMitigation
Secret exfiltration in promptsDLP scanning with block/redact actions
Prompt injectionInjection scoring and strict tool-use validation
Provider key exposureProvider keys stored in vault or external keys, never returned to clients
Privilege escalationRBAC with org-scoped ownership checks on every admin route

Permission profiles as safety boundaries

Permission profiles define what an agent can do on your machine. The built-in profiles let you choose a default posture without rewriting config. For sensitive work, start with restricted; for trusted repositories, use trusted-review; avoid danger-full-access unless the host already isolates processes.

toml
# ~/.gizzi/profiles/untrusted-audit.toml
[permissions]
approval_policy = "never"
sandbox_mode = "workspace-write"
network_access = false
allow_login_shell = false

[permissions.sandbox_workspace_write]
writable_roots = []

Overlay order matters. A profile is loaded after user defaults but before project overrides and CLI flags. That means a project-local .gizzi/config.toml can tighten settings, but it should not silently loosen safety settings without review.

Vault, audit, and compliance

Credentials belong in the vault, not in prompts or repository files. AllternitVault seals OAuth values and other secrets at rest using the API's token crypto layer. The plaintext is never returned by the credential list API, and revocation sets revoked_at without deleting the row, preserving an audit trail.

Audit logs cover administrative actions, key lifecycle events, and compliance requests. Every LLM request is recorded with tokens, cost, status, latency, and routing decision. Compliance endpoints let admins export or delete chats, projects, and artifacts when required.
