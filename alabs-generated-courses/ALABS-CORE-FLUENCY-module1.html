Module 1: Introduction to AI Fluency

Learn to read, steer, and verify AI systems using Allternit's own chat surface and agent-orchestration workflow. Fluency is not magic—it is a set of concrete practices you can apply today.

~5 lessons · ~30 minutes Source: surfaces/ai.allternit.com/src/views/ChatView.tsx

What is AI fluency?

AI fluency is the practical skill of collaborating with AI systems: picking the right model, writing clear prompts, knowing when to delegate, and—most importantly—reviewing every output before treating it as truth. Inside Allternit, that fluency is exercised through two primary surfaces.

  • ChatView — the main human-AI collaboration UI where users chat, select models, embed agent sessions, and inspect artifacts.
  • CLI Agent Orchestrator — the delegation layer that scopes work, spawns external CLI agents in isolated tmux sessions, monitors progress, and enforces a non-negotiable review phase.

Both surfaces share the same discipline: the human stays in the loop. Whether you are sending one message or delegating a multi-file refactor, you define the goal, inspect the result, and decide what ships.

Fluency principle: An AI tool is only as useful as the operator's ability to verify its work. The Allternit codebase encodes that principle in error handling, session lifecycle, and orchestrator review.

Inside ChatView: modes, models, and sessions

ChatView.tsx is the React component behind Allternit's chat experience. It supports three modes—chat, cowork, and code—and translates the chosen mode into an AgentModeSurface that controls which agent context is active.

tsx 
export function ChatView({ hideEmptyState = false, mode = 'chat', ... }) {
  const agentSurface: AgentModeSurface =
    mode === 'cowork' ? 'cowork'
    : mode === 'code' ? 'code'
    : 'chat';

  const { agentModeEnabled, selectedAgent } =
    useSurfaceAgentSelection(agentSurface);
}

The component then decides whether the conversation is a plain chat or an embedded agent session. That distinction determines which store holds the messages, how streaming is tracked, and whether the agent context strip is rendered.

tsx 
const activeIsLoading = isAgentSessionEmbedded
  ? nativeStreaming.isStreaming

const isChatEmpty = !isAgentSessionEmbedded && nativeMessages.length === 0;

// Only sessions bound to an agent render the context strip.
const hasAgentBinding = Boolean(
  embeddedAgentDescriptor.agentId || embeddedAgentDescriptor.agentName,

Sending a message

When the user presses send, handleSend resolves the correct session ID, creates a new backend session if needed, and streams the message through sendNativeMessageStream. Errors are caught and surfaced as actionable banners rather than silent failures.

tsx 
let sessionId = embeddedAgentSession.sessionId || chatId;
const hasLiveSession = Boolean(sessionId && sessionId.startsWith('ses_'));

if (!hasLiveSession) {
  sessionId = await useChatSessionStore.
    getState().createSession({
      name: text.trim().slice(0, 60) || 'New Session',
      sessionMode: 'regular',
    });
}

if (sessionId) {
  useChatSessionStore.getState().setActiveSession(sessionId);
  await sendNativeMessageStream(sessionId, { text: text.trim() });
}

Notice the guard: a valid live session ID starts with ses_. Without that prefix, ChatView creates a fresh session. This is a small but important example of state discipline in human-AI interfaces.

When chat is not enough: delegate with review

Some tasks span multiple files, builds, or test runs. For those, Allternit uses the CLI Agent Orchestrator. The orchestrator does not replace the human; it extends the human's reach by running an external CLI agent in its own tmux session and then requiring the orchestrator to review the result.

Core takeaway: Delegation without review is not fluency. The orchestrator's Phase 5 review is non-negotiable because the human operator must verify the executor's footprint and claims before the work is accepted.

Capstone: Design your AI-fluent workflow

Apply what you learned by mapping a real task through the Allternit surfaces. Pick a small change you might ask an AI to help with—such as adding a validation rule, renaming a component, or writing a test.

1. Choose the surface

Would this task be faster in ChatView, or does it need the orchestrator's isolated worktree? Justify your choice.

2. Write the prompt

Draft the exact message or task spec you would send. Include scope, constraints, and a deliverable sentinel.

3. Plan verification

List three concrete things you would check before accepting the AI's output. Reference ChatView's error handling or the orchestrator's review phase.

4. Document trade-offs

Note one risk of full automation and one safeguard from the codebase that mitigates it.
