Module 1: Cowork Workspaces and Context

Learn how Allternit's Cowork engine turns user identity, memory, and personas into a shared workspace for agent collaboration. You'll explore the core types that define a cowork session and see how context is scoped, stored, and recalled.

~5 lessons ~30 min packages/@allternit/cowork-engine

Core Concepts

A Cowork workspace is a collaboration surface where agents operate on behalf of a user. The engine is organized around three primitives: memory, personas, and approval gates. This module focuses on the first two.

Scoping Context

Every memory entry is tied to a userId. Entries can optionally be narrowed to a projectId or a sessionId, making it easy to keep long-lived facts separate from short-term turn-by-turn context.

FieldScopeExample
userIdUser-widePreferences, skills, cross-project facts
projectIdProject-wideArchitecture decisions, codebase conventions
sessionIdSession-onlyCurrent task, draft outputs, temporary context

Memory Entry Types

The engine classifies memory into four types, each with a distinct retrieval purpose:

  • fact — Verified knowledge about the user, project, or domain.
  • preference — User tastes, defaults, and stylistic choices.
  • skill — Capabilities or reusable workflows the agent should remember.
  • context — General, often transient, session background.

Personas

A CoworkPersona defines how an agent behaves inside a workspace. It bundles a systemPrompt, an allowed tools list, and a default flag. Cowork ships with three built-in personas — Researcher, Engineer, and Analyst — so workspaces can be useful immediately.

Design note: Personas and memory are intentionally separate. Personas shape behavior; memory shapes what the agent knows about the current workspace.

Walkthrough: The Workspace Types

The public surface of the package is tiny — src/index.ts re-exports memory, approval, and persona modules — but the type contracts tell the story. Here are the shapes that drive every cowork interaction.

typescript 
// packages/@allternit/cowork-engine/src/memory/types.ts

export type CoworkMemoryEntryType = 'fact' | 'preference' | 'skill' | 'context';

export interface CoworkMemoryEntry {
  id: string;
  userId: string;
  projectId: string | null;
  sessionId: string | null;
  content: string;
  type: CoworkMemoryEntryType;
  tags: string[];
  source: string | null;
  createdAt: Date;
}

export interface CoworkMemoryCreateInput {
  userId: string;
  projectId?: string | null;
  sessionId?: string | null;
  content: string;
  type?: CoworkMemoryEntryType;
  tags?: string[];
  source?: string | null;
}

Creating a memory entry only requires a user and some content. Everything else is optional, so callers can decide how narrowly they want to scope the record.

typescript 
// packages/@allternit/cowork-engine/src/personas/types.ts

export interface CoworkPersona {
  id: string;
  userId: string;
  name: string;
  description: string | null;
  systemPrompt: string;
  tools: string[];
  isDefault: boolean;
  createdAt: Date;
  updatedAt: Date;
}

export interface CoworkPersonaCreateInput {
  userId: string;
  name: string;
  description?: string;
  systemPrompt: string;
  tools?: string[];
  isDefault?: boolean;
}

export const BUILT_IN_PERSONAS = [
  {
    name: 'Researcher',
    tools: ['web_search', 'read_file', 'write_file'],
    isDefault: false,
  },
  {
    name: 'Engineer',
    tools: ['read_file', 'write_file', 'run_command', 'web_search'],
    isDefault: true,
  },
  {
    name: 'Analyst',
    tools: ['read_file', 'write_file', 'run_command'],
    isDefault: false,
  },
] as const;

Notice that personas are also userId-scoped, but they carry a default flag. The store guarantees that only one persona per user is marked default, falling back to the alphabetically first persona if no default exists.

Try it: Open packages/@allternit/cowork-engine/src/index.ts and trace the exports. Memory and personas each expose a create*Store factory that wires the types to a Prisma client.

Capstone: Bootstrap a Cowork Workspace

Build a small workspace initializer using the real Cowork engine types and stores. Your solution should run against a Prisma-backed store and leave the workspace ready for an agent session.

Seed Personas

Call ensureBuiltIns(userId) so Researcher, Engineer, and Analyst are available.

Capture Context

Create a context memory entry scoped to a projectId and sessionId.

Recall by Type

List memory entries filtered by type: 'preference' and by a tag such as output-format.

Select Default Persona

Fetch the default persona for the user and return its name and tool list.
