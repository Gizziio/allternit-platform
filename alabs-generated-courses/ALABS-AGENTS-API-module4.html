From document to text

Retrieval-Augmented Generation (RAG) starts with raw documents. Before an agent can answer questions from a knowledge base, the platform must turn PDFs, Word files, spreadsheets, and slides into plain text that a model can consume.

The @allternit/office-file-parse package handles this in production. Its parseFileToText function reads a file path, inspects the extension, and dispatches to the right parser for docx, pptx, xlsx, or pdf. It also recognizes image formats and returns them as kind: 'image' so multimodal models can consume raw bytes instead of hallucinated OCR text.

  • One function, many formats. parseFileToText normalizes every attachment to a ParsedFile object.
  • Images stay images. PNG, JPEG, GIF, and WebP are not OCR'd; they are passed to vision-capable providers.
  • Errors are data, not crashes. A malformed PDF returns { ok: false, error: '...' } so the RAG pipeline can log and continue.

Parse-first principle: Never feed raw binary documents to an embedding model. Always extract or flag content first.

Chunking and embeddings

Once a document is text, the next job is to split it into passages and turn each passage into a vector. Allternit's AllternitEmbeddings.create endpoint resolves the right provider and URL from the harness config mode, so the same code works in BYOK, cloud, and local deployments.

typescript 
import { AllternitEmbeddings } from '@allternit/sdk/ai-runtime/embeddings';

const embeddings = new AllternitEmbeddings({
  mode: 'byok',
  byok: {
    openai: { apiKey: process.env.OPENAI_API_KEY! },
  },
});

const chunks = [
  'Refunds are accepted within 30 days with original receipt.',
  'Enterprise customers may request a dedicated support channel.',
];

const result = await embeddings.create({
  model: 'text-embedding-3-small',
  input: chunks,
});

console.log(result.data[0].embedding.length); // 1536

Chunk size is a trade-off. Small chunks retrieve precisely but can lose surrounding context; large chunks preserve context but dilute relevance scores. A typical RAG pipeline on Allternit targets 200–400 tokens per chunk with a small overlap to avoid splitting sentences.

Retrieval and hybrid search

With vectors stored in an Allternit memory store, a user question is embedded the same way and compared against the index. The simplest pipeline returns the top-k nearest neighbors by cosine similarity.

In production, Allternit uses a hybrid of vector similarity and keyword search (BM25). Dense retrieval captures paraphrases and conceptual matches; sparse retrieval captures rare tokens like product codes, IDs, and names. The two scores are combined with a weighted rank fusion to produce the final passage list.

Hybrid search rule: Combine dense + keyword signals so exact identifiers and conceptual synonyms both surface.

Grounding the agent

Retrieved passages are worthless if the model ignores them. Allternit uses the support-triage and RAG playbook patterns from docs/public/guides/use-case-playbooks.md: the system prompt instructs the model to answer using only the provided passages and cite each one with [index].

text 
Answer the question using only the provided passages. Cite each passage with [index].
If the answer is not in the passages, say so.

Passages:
[1] Refunds are accepted within 30 days with original receipt.
[2] Enterprise customers may request a dedicated support channel.

Behind the scenes, agent-context-pack.ts assembles the final context. It parses SOUL.md for trust tiers, HEARTBEAT.md for scheduled tasks, and TOOLS.md for available tools, then combines them with the retrieved passages into a structured ContextPack. The pack includes a hash for caching and an expiry so the agent refreshes context before it goes stale.

  • Trust tiers. Tier 1 rules always apply; Tier 3 actions require explicit permission.
  • Citations. Passages are labeled so the model can attribute claims.
  • Refresh. Context packs expire after five minutes by default.
