Module 4: Discernment: Evaluating Agent Outputs

Discernment is the third D of AI fluency: the discipline of reviewing agent outputs before accepting them as truth. This module grounds evaluation in Allternit's agent-review engine and use-case playbooks.

5 lessons · ~40 minutes Source: surfaces/ai.allternit.com/src/lib/agents/agent-review.ts

Why evaluation is non-negotiable

Agents can produce fluent, plausible, and wrong outputs. Discernment is not about distrust; it is about verification. The Allternit agent-review engine codifies this by refusing to act on outputs that lack evidence, conflict with other agents, or touch sensitive domains.

At the heart of the engine is the buildTeamAlignment function. It receives checkpoints from active bots, groups them by task, detects conflicts, flags missing evidence, and escalates sensitive work to a human owner.

Discernment rule: never ship an agent output you cannot verify. Evidence can be a URL, file path, commit hash, or explicit verification statement.

Evaluation checklists from the playbooks

The use-case playbooks in docs/public/guides/use-case-playbooks.md give concrete checklists for common tasks. Apply them every time you delegate work to an agent.

Customer support triage

  • Category accuracy on a labeled test set.
  • No drafted response when escalate is true.
  • Response tone matches brand guidelines.

Legal document summarization

  • Summary covers scope, term, and payment.
  • Risk flags include supporting quotes.
  • No hallucinated clauses.

Code review assistant

  • Catches the seeded security issue.
  • Does not flag false positives on style-only changes.
  • Suggested fixes compile or are syntactically plausible.

RAG Q&A

  • Answers are grounded in retrieved passages.
  • Citations are accurate.
  • Refuses appropriately when context is insufficient.

The evaluation loop

A complete evaluation loop has four stages: structure, citations, verification, and acceptance. If any stage fails, reject the output and iterate the prompt or the task spec. 

flowchart LR
    A[Agent Output] --> B{Structured?}
    B -->|No| C[Require schema]
    B -->|Yes| D[Check citations]
    D --> E{Evidence?}
    E -->|No| F[Flag missing evidence]
    E -->|Yes| G[Run test / verify]
    G --> H{Passes?}
    H -->|No| I[Reject / revise]
    H -->|Yes| J[Accept with note]
    F --> K[Escalate to human]
    I --> L[Iterate prompt]
    L --> A

The agent-review engine automates parts of this loop. It flags missing evidence, conflicting owners, conflicting statuses, and conflicting conclusions. It also maintains a prohibited-actions list covering payment, credentials, deploy, production, client messages, and publishing.
