# Upstream compatibility surface (CLAUDE_CODE_ env vars, upstream URLs, package names)

The CLI is a fork of an upstream product (Claude Code). This document is the
triage record for what still carries upstream identifiers, and why.

## Environment variables

### Dual-named: GIZZI_ first, CLAUDE_CODE_ fallback

These vars are **set by the CLI itself** (runtime markers, session context for
child processes). Writes go through `setGizziEnv()` (sets both forms); reads
go through `readGizziEnv()` (prefers `GIZZI_`, falls back to
`CLAUDE_CODE_`). See `src/shared/utils/gizziEnv.ts`.

| Canonical | Legacy |
|-----------|--------|
| `GIZZI_ENTRYPOINT` | `CLAUDE_CODE_ENTRYPOINT` |
| `GIZZI_SIMPLE` | `CLAUDE_CODE_SIMPLE` |
| `GIZZI_AGENT` | `CLAUDE_CODE_AGENT` |
| `GIZZI_TASK_LIST_ID` | `CLAUDE_CODE_TASK_LIST_ID` |
| `GIZZI_COORDINATOR_MODE` | `CLAUDE_CODE_COORDINATOR_MODE` |
| `GIZZI_SESSION_ACCESS_TOKEN` | `CLAUDE_CODE_SESSION_ACCESS_TOKEN` |
| `GIZZI_SESSION_ID` | `CLAUDE_CODE_SESSION_ID` |

Why dual-name instead of rename: nested sessions, SDK consumers, and CI setups
follow upstream docs and set the `CLAUDE_CODE_` form. Child-process env
filters (`isFilteredChildEnvKey` in `src/runtime/drivers/local-cli-driver.ts`)
strip both forms of the internal runtime markers (`ENTRYPOINT`, `SESSION_ID`).

### Kept as CLAUDE_CODE_ reads (compat surface, not renamed)

Every remaining `CLAUDE_CODE_*` reference below is a variable the CLI **reads
but never sets**. They are kept because they are part of the upstream/SDK
user-facing configuration contract — users following upstream documentation,
the Claude Agent SDK, or the GitHub Action set these names. Renaming them
would silently break those users; a future deprecation window should print a
warning and map them onto `GIZZI_*` equivalents.

Notable kept groups:

- **Auth/provider**: `CLAUDE_CODE_OAUTH_TOKEN`, `CLAUDE_CODE_USE_BEDROCK`,
  `CLAUDE_CODE_USE_VERTEX`, `CLAUDE_CODE_USE_FOUNDRY`,
  `CLAUDE_CODE_SKIP_*_AUTH`, `CLAUDE_CODE_CLIENT_CERT`, ... — upstream-documented
  auth switches; also consumed by the upstream GitHub Action ecosystem.
- **Remote/control plane**: `CLAUDE_CODE_REMOTE`, `CLAUDE_CODE_SSE_PORT`,
  `CLAUDE_CODE_SESSION_ACCESS_TOKEN` (read side), ... — the remote-session
  protocol speaks these names to upstream session-ingress.
- **Feature flags / managed env**: declared in
  `src/cli/ui/ink-app/utils/feature-flags.ts` and `managedEnvConstants.ts` as
  env-var-name registries; renaming the registry entries renames the contract.
- **`CLAUDE_CODE_20250219_BETA_HEADER`** — not an env var; a code constant
  holding the API beta-flag string sent to the model API. The *value* is an
  API contract and must stay; the identifier was renamed
  (`GIZZI_BETA_HEADER_20250219`).

## URLs

Repointed to Allternit-owned hosts (canonical list in
`src/shared/constants/cloudUrls.ts`):

- Docs links `code.claude.com/docs/en/*` → `docs.gizziio.com/*` (settings
  validation tips, MCP/sandbox/trust dialogs, preflight checks, keybindings).
- Privacy/consent links → `allternit.io/legal/privacy`,
  `allternit.io/legal/terms`, `www.allternit.io/news/updates-to-our-consumer-terms`.
- Usage/billing links → `console.allternit.com/*`.
- Product surfaces: web app → `remotecontrol.allternit.com`; install →
  `install.gizziio.com`; Chrome setup → `docs.gizziio.com`.

Kept upstream (functional dependency, not branding):

- `api.anthropic.com` / `api-staging.anthropic.com` — the model API endpoint.
- `code.claude.com/docs/en/claude_code_docs_map.md` — fetched at runtime by
  the guide agent (`claudeCodeGuideAgent.ts`); `docs.gizziio.com` has no
  equivalent map (verified 404).
- `code.claude.com` in WebFetch preapproved domains — enables that runtime
  fetch without permission prompts.
- `claude.ai/oauth/*` endpoints — the OAuth contract (client metadata,
  authorize).
- `claude.ai/settings/connectors`, `claude.ai/code/scheduled`,
  `claude.ai/code/onboarding` in the remote-agent skill/task — these operate
  the upstream hosted remote-agent platform, which the fork does not host.
- `claude-ai.staging.ant.dev` — internal upstream staging host references.

## Package names

- `@anthropic-ai/sdk` (and `declare module '@anthropic-ai/...'` shims) — the
  real Anthropic TypeScript SDK dependency; kept.
- `@anthropic-ai/claude-code` — referenced only in leftover-install detection
  (`doctor`, native installer cleanup) to help migrating users uninstall the
  upstream package; kept on purpose.
- A previous partial rebrand had introduced the bogus scope
  `@anthropic-ai/gizzi`; those references were corrected to the true upstream
  package name in this slice.
